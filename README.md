# Speedll Connect

**یک کلاینت VPN چندسکویی با تجربه کاربری ساده، مدرن و قابل استفاده برای همه**

- نام محصول: `Speedll Connect`
- وضعیت مخزن: زیرساخت اولیه / Pre-alpha
- رابط کاربری: Flutter (روشن و تاریک)
- هسته‌های مورد ارزیابی: sing-box و Xray-core
- سیستم‌عامل‌های هدف: Android، iOS، Windows، macOS و Linux
- مدل محصول: استفاده عمومی رایگان + امکانات و اتصال حساب اختصاصی Speedll

> **وضعیت مهم:** این مخزن هنوز یک VPN Client عملیاتی نیست. صفحه Flutter صرفاً پیش‌نمایش UI است و هیچ تونل، پراکسی یا اتصال واقعی ایجاد نمی‌کند. هسته‌ها عمداً به پروژه اضافه نشده‌اند؛ ابتدا باید سازگاری، روش بسته‌بندی و تعهدات مجوزی آن‌ها بررسی و ثبت شود.

## از کجا شروع کنیم؟

1. `AGENTS.md` را کامل بخوانید؛ قواعد کار همه دستیارهای کدنویسی در آن ثبت شده است.
2. `docs/ROADMAP_FA.md` نقشه اصلی پروژه و چک‌لیست مراحل است.
3. `docs/ARCHITECTURE_FA.md` معماری پیشنهادی را توضیح می‌دهد.
4. `docs/ENGINE_EVALUATION_FA.md` معیار انتخاب sing-box و Xray و ملاحظات مجوز را دارد.
5. `docs/AI_HANDOFF_PROMPT_FA.md` پرامپت آماده برای ادامه کار در VS Code است.
6. هیچ مرحله‌ای را بدون تکمیل معیار خروج همان مرحله شروع‌شده یا تمام‌شده اعلام نکنید.

## ساختار مخزن

```text
Speedll-Connect/
├── app/                       # برنامه Flutter و رابط مشترک
├── engine/                    # ارزیابی و Adapter هسته‌ها؛ هنوز بدون باینری
├── subscription/              # مدل‌ها، Parserها، اعتبارسنجی و تبدیل قالب‌ها
├── platform/                  # اتصال بومی هر سیستم‌عامل
├── backend/                   # قرارداد API حساب Speedll (اختیاری و جدا از مسیر ترافیک)
├── docs/                      # معماری، نقشه راه، امنیت، مجوز، تست و انتشار
├── tests/                     # تست‌های مشترک و نمونه‌های Sanitized
└── .github/                   # قالب گزارش باگ و درخواست قابلیت
```

## پیش‌نیاز توسعه محلی

- Flutter SDK و Dart سازگار با نسخه تعیین‌شده در `app/pubspec.yaml`
- VS Code به همراه افزونه‌های Flutter و Dart
- ابزار بومی هر سیستم‌عامل مقصد؛ برای نمونه Android SDK/NDK برای Android و Xcode برای iOS/macOS
- Go فقط پس از تثبیت روش ساخت و ادغام موتورهای Go-based

نسخه ابزارها را در اولین اجرای فاز صفر ثبت کنید. نسخه‌های نصب‌شده در سیستم سازنده، الزاماً نسخه‌های مناسب CI یا انتشار نیستند.

## آماده‌سازی پروژه Flutter و اجرای پیش‌نمایش UI

در این تحویل، پوشه‌های میزبان Flutter برای سیستم‌عامل‌ها هنوز تولید نشده‌اند؛ چون Flutter SDK در محیط ساخت این اسکلت نصب نبود. پس از نصب Flutter، یک‌بار اسکریپت متناسب با سیستم خود را اجرا کنید:

PowerShell:

```powershell
.\scripts\bootstrap_flutter_platforms.ps1
```

Linux/macOS:

```bash
./scripts/bootstrap_flutter_platforms.sh
```

این اسکریپت پوشه‌های پایه Android، iOS، Windows، macOS و Linux را ایجاد می‌کند و فایل‌های دستی رابط کاربری را بازمی‌گرداند. بعد از اجرا حتماً `git diff` را بازبینی کنید.

سپس:

```bash
cd app
flutter pub get
flutter analyze
flutter test
flutter run
```

برای build و اجرای هر سیستم‌عامل، ابزارهای بومی همان سیستم‌عامل باید نصب باشند. توسعه و build نهایی iOS/macOS به macOS و Xcode نیاز دارد. مستندات Flutter درباره پلتفرم‌ها: <https://docs.flutter.dev/reference/supported-platforms>

## اصول غیرقابل مذاکره

- هیچ وضعیت اتصال موفقی را شبیه‌سازی یا جعل نکنید.
- هیچ UUID، رمز، توکن یا لینک فعال مشتری را وارد Git، تست، لاگ یا Issue نکنید.
- UI نباید به پیاده‌سازی موتور وابسته شود؛ همه چیز از قراردادهای Engine Adapter عبور کند.
- API حساب Speedll نباید در مسیر عبور ترافیک VPN قرار بگیرد.
- پشتیبانی از یک قالب لینک، به‌تنهایی به معنی اجرای کامل تمام قابلیت‌های آن نیست.
- قبل از توزیع هر Engine، مجوز همان نسخه و وابستگی‌های آن را دوباره بررسی کنید.
- هر تغییر معماری مهم باید در `docs/decisions/` ثبت شود.

## مالکیت و مجوز پروژه

مجوز نهایی خود Speedll Connect هنوز انتخاب نشده است. تا زمان تصمیم رسمی، فایل مجوز نهایی اضافه نکنید و این مخزن را با مجوز فرضی منتشر نکنید. مجوز کدهای وابسته به sing-box و Xray باید جداگانه و دقیق رعایت شود. جزئیات در `docs/ENGINE_EVALUATION_FA.md` و `docs/LEGAL_AND_LICENSE_CHECKLIST_FA.md` آمده است.
